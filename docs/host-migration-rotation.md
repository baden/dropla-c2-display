# Миграция ведущего ПО на прошивку с поворотом экрана

Документ для сопровождения ведущего ПО (хоста), которое уже работает с
`firmware/c2_display` и должно быть совместимо с прошивкой, где появился
поворот изображения.

- Предыдущая прошивка: коммит `4ee906f` (поворота нет).
- Прошивка с поворотом: коммит `495fa98` и новее.
- Версия протокола не менялась: `LINK_VERSION = 1`.

## 1. Коротко

Формат кадра, CRC, `seq`, типы сообщений, `PING/PONG`, `TELEMETRY`, `NOTIFY`
и `SOUND` **не изменились**. Старое ведущее ПО продолжает работать без правок.

Добавлен только необязательный тег `CONFIG 0x02` — поворот изображения.
Старые прошивки его игнорируют, новые применяют. Если хост не отправляет этот
тег, панель использует сохранённое значение из NVS (по умолчанию `0°`).

Главное, что нужно учесть при миграции:

1. Поворот **сохраняется в NVS** и переживает перезагрузку панели.
2. Единицы одометра по-прежнему сбрасываются в `km` после перезагрузки.
3. У `CONFIG` нет подтверждения (ACK), поэтому хост не может программно узнать,
   применила ли панель поворот. Старая прошивка просто проигнорирует тег.
4. Отдельной версии прошивки в протоколе нет; `PONG` отдаёт версию протокола
   (`1`), а не наличие функции поворота.

## 2. Что именно изменилось

### 2.1. Протокол

| Что | Было | Стало |
|---|---|---|
| `CONFIG 0x01` (единицы одометра) | есть | без изменений |
| `CONFIG 0x02` (поворот) | нет | `u16 LE`, градусы: `0`, `90`, `180`, `270` |
| Остальные сообщения | — | без изменений |
| `LINK_VERSION` | `1` | `1` |

Тег поворота:

```text
CONFIG payload:
  count = 1
  02 02 5A 00        # tag=0x02, len=2, value=90 (u16 LE)
```

`len` должен быть равен `2`. Значения `0`, `90`, `180` и `270` допустимы;
всё остальное панель игнорирует, сохраняя текущий поворот. Если `len < 2`,
тег тоже игнорируется (в лог панели пишется предупреждение).

### 2.2. Прошивка

- Поворот выполняется аппаратно через `MADCTL` ST77916, а не программным
  поворотом LVGL. Координаты протокола и раскладка UI не меняются.
- Применение — сразу, без перезагрузки; после смены выполняется полная
  перерисовка экрана.
- Значение хранится в NVS: namespace `c2disp`, ключ `rot`.
- При старте сохранённый поворот применяется после `LCD_Init()` и до первого
  кадра LVGL, поэтому анимация включения тоже поднимается в нужной ориентации.
- Исправлена внутренняя ошибка QSPI в `panel_st77916_swap_xy()`; для ведущего
  ПО это не меняет ничего, но без исправления смена `MADCTL` на этой панели
  не работала бы.
- Плановый тег BMS в `docs/bms-ble-plan.md` перенесён с `0x02` на `0x03`.
  BMS пока не реализован; на текущий протокол это не влияет.

## 3. Совместимость версий

| Ведущее ПО | Прошивка | Что получится |
|---|---|---|
| старое, шлёт только `0x01` | старая | базовое поведение, без изменений |
| старое, шлёт только `0x01` | новая | всё работает; поворот берётся из NVS, старый хост не может его изменить |
| новое, шлёт `0x01` + `0x02` | старая | телеметрия, уведомления, звук и единицы работают; тег `0x02` молча игнорируется, экран не поворачивается |
| новое, шлёт `0x01` + `0x02` | новая | полная поддержка поворота |

Выводы:

- **Обновлять прошивку и хост можно в любом порядке.** Формат кадра не
  ломается ни в одну сторону.
- Если хост обновили раньше панели, поворот просто не будет работать до
  обновления прошивки. Ошибки в протоколе при этом нет.
- Если панель обновили раньше хоста, старый хост продолжит работать. Но если
  на панели уже был сохранён, например, `90°`, старый хост его не сбросит:
  он не знает тега `0x02`.

## 4. Обязательные изменения в ведущем ПО

Для сохранения текущего поведения **ничего менять не обязательно**. Проверьте
только, что хост:

- отправляет `CONFIG` с тегом `0x01` как раньше;
- не считает, что `CONFIG` должен вернуть ACK;
- не завязан на конкретную ориентацию экрана.

Если хост должен гарантировать положение экрана (например, киоск или
фиксированный монтаж), добавьте в стартовую конфигурацию тег `0x02` с нужным
значением — даже если это `0°`. Тогда результат не зависит от того, что
осталось в NVS от предыдущих тестов или другого хоста.

## 5. Изменения в клиентских библиотеках

### 5.1. Rust (`tools/rust-c2link`)

`Display::config(&Config)` не изменился. В `Config` добавлено публичное поле
`rotation: Option<Rotation>`, поэтому **структурные литералы** старого вида
перестанут компилироваться:

```rust
// Было:
let cfg = Config { odometer_unit: Some(OdometerUnit::Km) };

// Стало — вариант 1, с builder:
let cfg = Config::default().odometer_unit(OdometerUnit::Km);

// Стало — вариант 2, если нужен именно литерал:
let cfg = Config {
    odometer_unit: Some(OdometerUnit::Km),
    ..Default::default()
};
```

Если хост не использовал структурные литералы, а строил конфиг через
`Config::default().odometer_unit(...)`, изменения не требуются.

Чтобы включить поворот:

```rust
use c2link::{Config, OdometerUnit, Rotation};

dev.config(
    &Config::default()
        .odometer_unit(OdometerUnit::Km)
        .rotation(Rotation::Deg90),
)?;
```

`Rotation::degrees()` возвращает `u16` (`0`, `90`, `180`, `270`). Не пытайтесь
получить градусы через `as u8`: `270` в байт не помещается, а проводной формат
специально сделан двухбайтовым.

Старые `Config`-payload'ы без тега `0x02` декодируются как `rotation: None`.
Неизвестные теги, как и раньше, пропускаются.

### 5.2. Python (`tools/c2link.py`)

Сигнатура расширена в конец, старые позиционные вызовы сохранены:

```python
# Было и осталось рабочим:
ser.write(config_frame("km"))
ser.write(config_frame("mi", extra_tlv_bytes))

# Новое — только по ключу rotation:
ser.write(config_frame("km", rotation=90))
```

Второй позиционный аргумент — по-прежнему `extra`, а не `rotation`. Не
передавайте поворот вторым позиционным аргументом.

CLI:

```bash
py tools/c2link.py --port COM4 config --rotation 90
```

Команда `config` всегда добавляет тег `0x01` (по умолчанию `km`). Если на
панели нужны мили, укажите явно:

```bash
py tools/c2link.py --port COM4 config --odo mi --rotation 90
```

`demo --rotation 90` делает то же самое при старте демо-потока.

### 5.3. Свой кодировщик

Добавьте в TLV один элемент:

```text
tag   = 0x02
len   = 2
value = degrees (u16 little-endian)
```

Увеличьте `count` на 1 и пересчитайте CRC кадра. Пример для `90°`:

```text
payload: 01 02 02 5A 00
```

Если хост умеет отправлять только один TLV, можно отправлять только поворот
(`count = 1`). Единицы одометра при этом не изменятся.

## 6. Рекомендуемый порядок миграции

1. **Обновите прошивку.** Старый хост должен продолжить работать; проверьте
   телеметрию, уведомления, звук, `PING/PONG` и единицы одометра.
2. **Проверьте ориентацию.** Если в NVS уже было сохранено значение, панель
   поднимется в нём. При необходимости сбросьте в `0°` новым клиентом.
3. **Добавьте поворот в хост.** Решите, будет ли хост отправлять `0x02` при
   каждом подключении или только по команде оператора.
4. **Проверьте persistence.** Поставьте `90°`, выключите и включите панель,
   убедитесь, что анимация включения и рабочий экран уже повёрнуты.
5. **Проверьте старый хост.** Отправьте `CONFIG` только с тегом `0x01` и
   убедитесь, что сохранённый поворот не сбрасывается.
6. **Проверьте откат.** При необходимости верните старую прошивку и убедитесь,
   что старый хост работает; поворот при этом будет проигнорирован.

## 7. Готовые кадры для проверки

Формат: `A5 5A | 0x13 | seq | len(LE16) | payload | crc16(LE16)`.
Ниже `seq = 4` только для примера. Панель принимает любой `seq`; если меняете
`seq`, пересчитайте CRC по алгоритму из
[`link-protocol.md`](link-protocol.md).

Только поворот (`count = 1`, без тега одометра):

| Поворот | Кадр |
|---|---|
| `0°` | `A5 5A 13 04 05 00 01 02 02 00 00 5B 39` |
| `90°` | `A5 5A 13 04 05 00 01 02 02 5A 00 2F D8` |
| `180°` | `A5 5A 13 04 05 00 01 02 02 B4 00 92 EB` |
| `270°` | `A5 5A 13 04 05 00 01 02 02 0E 01 75 0A` |

Одометр `km` + поворот `90°` (`count = 2`):

```text
A5 5A 13 04 08 00 02 01 01 00 02 02 5A 00 21 BD
```

Старый кадр только с единицами (`mi`, без поворота) остаётся валидным:

```text
A5 5A 13 04 04 00 01 01 01 01 0C 61
```

## 8. Подводные камни

### 8.1. Старый хост не сбрасывает сохранённый поворот

Это главное поведенческое отличие. Новая прошивка при получении `CONFIG`
без тега `0x02` не трогает сохранённое значение. Если панель стоит криво после
тестов, а под рукой только старый хост, сделайте одно из трёх:

- один раз отправьте кадр поворота `0°` из таблицы выше;
- используйте новый клиент: `config --rotation 0`;
- при полной перепрошивке с очисткой NVS значение тоже сбросится (но вместе
  с другими NVS-данными).

Если старый хост должен всегда возвращать экран в `0°`, добавьте в его
`CONFIG` тег `0x02` со значением `0` — это единственный способ сделать
поведение детерминированным.

### 8.2. Новый хост на старой прошивке

Старая прошивка не знает тег `0x02` и пропускает его как неизвестный. Это
штатное поведение, а не ошибка парсера. Поворот не применится, ACK не будет,
телеметрия продолжит идти. Не считайте отправку `CONFIG` гарантией того, что
экран повернулся.

### 8.3. Нет запроса версии прошивки

`PONG` содержит версию протокола (`1`), но не версию прошивки и не список
возможностей. Программно отличить прошивку с поворотом от старой по протоколу
нельзя. Варианты:

- вести учёт версий прошивки в парке устройств;
- проверять поворот визуально/по логу панели;
- в будущем добавить отдельный capability-тег, но это уже изменение протокола.

### 8.4. Единицы одометра и поворот живут по-разному

После перезагрузки панели единицы одометра снова `km`, а поворот остаётся
сохранённым. Не связывайте эти настройки в одну «конфигурацию, которая
сбрасывается». Хосту, которому нужны мили, по-прежнему нужно отправлять
`0x01` после каждого старта панели.

### 8.5. Прошивка с полной очисткой флеша

Обычная заливка скетча через Arduino/`arduino-cli` не стирает NVS: поворот
сохраняется. Если производственная прошивка делает полное стирание
(`erase_flash`/erase-all), NVS очищается — панель стартует с `0°`. В этом
случае ведущее ПО должно отправлять нужный поворот при каждом подключении.

### 8.6. Понижение версии прошивки

Старая прошивка не читает ключ `rot`. Экран поднимется в `0°`, даже если в NVS
осталось `90°`. Значение не удаляется: при повторном обновлении на прошивку с
поворотом оно снова начнёт действовать. Если это нежелательно, сбросьте
поворот в `0°` перед откатом.

### 8.7. Направление 90° и 270°

Направление зависит от партии панели. Если на конкретном экземпляре `90°` и
`270°` выглядят наоборот, это исправляется в прошивке (`Display_ST77916.cpp`,
случаи `90` и `270`), а не подменой значений в хосте. Хост должен предоставлять
пользователю оба варианта, а не предполагать «по часовой стрелке».

### 8.8. Поворот не меняет координаты протокола

Телеметрия, уведомления, звуки и `PING/PONG` не зависят от ориентации. Тач в
этой прошивке не используется, поэтому преобразовывать координаты не нужно.

## 9. Чек-лист миграции

- [ ] Старый хост работает с новой прошивкой: телеметрия, `NOTIFY`, `SOUND`,
      `PING/PONG`, единицы одометра.
- [ ] `CONFIG` с тегом `0x01` по-прежнему применяется.
- [ ] `CONFIG` с тегом `0x02` и `len = 2` применяет `0/90/180/270`.
- [ ] Недопустимое значение (например, `45`) игнорируется, текущий поворот
      остаётся.
- [ ] Поворот применяется без перезагрузки.
- [ ] Поворот переживает выключение/включение панели.
- [ ] Старый хост (только `0x01`) не сбрасывает сохранённый поворот.
- [ ] Новый хост на старой прошивке не ломает телеметрию (тег игнорируется).
- [ ] Проверены оба направления `90°` и `270°`, нет зеркалирования.
- [ ] Проверен откат на старую прошивку.
- [ ] Нет регрессий: анимация включения, `Link lost`, низкий заряд,
      уведомления, звуки, одометр.

## 10. Откат

1. Залейте предыдущую прошивку (`4ee906f` или свою стабильную).
2. Убедитесь, что старый хост отправляет `CONFIG` с тегом `0x01` и не ждёт
   подтверждения на `0x02`.
3. Если новый хост продолжает отправлять `0x02`, старая прошивка просто
   пропустит тег; это безопасно.
4. Если нужно вернуть `0°` перед откатом, сделайте это новым клиентом:
   `config --rotation 0` (или кадром из таблицы).
